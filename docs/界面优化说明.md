# 2.0：从「换了个颜色」到「能当手机 App 用」

## 1.0 为什么没解决问题

1.0 只做了一层 CSS 换色，你说得对——**三个关键问题一个都没碰到**：

| 现象 | 真实原因（查上游源码确认） |
|---|---|
| 打开还要点「进入工作台」 | `MainActivity` 注释里写着「刻意不自动跳进工作台」，是两页结构：启动页 + 全屏工作台 |
| 点左上角「上传」没反应 | 上游 `web/src/pages/FilesPage.tsx` 用隐藏的 `<input type="file">` + `fileInputRef.current?.click()`；Android WebView 默认不实现 `WebChromeClient.onShowFileChooser`，点击后**静默失败**。旧代码还把 `allowContentAccess` 设成了 `false`，选中文件也读不出来 |
| 创建不了新工作区 | 上游 `/api/chat/workspaces` 的数据来自桌面端 `projects.db` 与仓库发现缓存（`hermes_cli/web_routers/chat_workspaces.py`）。安卓是 headless proot，没有桌面端，这份数据恒为空，下拉框只剩「默认 / 自定义路径」；而后端 `resolve_chat_cwd()` 要求路径必须是**真实存在的目录**，随手填一个名字直接 400 |

所以这轮不是再刷一层漆，是把上面三处功能链补上，同时把交互重做成手机的样子。

## 一、去掉启动页，打开就在里面

`MainActivity` 从「两页」改成「单页 App 壳」：

- 删掉 `launcherPage` 和「进入工作台」按钮；
- 服务照旧后台自动拉起，启动过程只是一张**会自动淡出的覆盖卡片**（进度 / 状态 / 可展开日志），
  条件是 `服务 READY && 页面 onPageFinished`，不需要用户点任何东西；
- 1.0 启动页上的设置 / 日志 / 重启 / 导出 / 重装全部搬到顶栏和「更多」里，一个不少。

## 二、把 WebView 缺的能力补齐

| 能力 | 实现 |
|---|---|
| 文件选择 | `onShowFileChooser` + `onActivityResult`，支持 `clipData` 多选、取消不卡死 |
| 内容读取 | `allowContentAccess = true` |
| 下载落盘 | `DownloadListener` 处理 `data:`（base64 解码写入 Download 目录）与外链 |
| 原生导入 | 「+」→ 上传文件到工作区，用 `ACTION_OPEN_DOCUMENT` 选文件后复制到工作目录 |
| 返回键 | 先回退网页历史，到底后「再按一次退出」（标准 App 行为） |

## 三、工作区：绕开桌面数据源，在手机侧闭环

新增 `Workspaces.kt` + 悬浮「+」面板：

1. 输入名字 → 在手机共享存储里 `mkdirs()` 建**真实目录**（proot 已 bind `/storage/emulated/0`，后端 `isdir` 能通过）；
2. 把路径写进面板的 `hermes-chat-workspace:<profile>` localStorage 键（`WebBridge.openWorkspace` 一次原子脚本完成写入 + 跳 `/chat`，避免异步导航打断脚本）；
3. `/chat` 整页重挂载后就会用这个目录开新会话；
4. 已创建的工作区在「+」面板里列出来，点一下即可切换。

网页里原有的工作区下拉框保持原样，只是现在终于有东西可选了。

## 四、像手机 App：原生壳 + 单栏卡片流

**原生部分**（你看得见、点得到的）：

- 顶栏：圆形设置键 + 胶囊标题（状态点 + 当前工作区名）+ 圆形更多键；
- 底部 5 Tab：会话 / 终端 / 文件 / 技能 / 设置；
- 右下角悬浮「+」：新建工作区、切换、上传文件、打开终端、刷新；
- 浅色状态栏、大圆角白卡片、蓝紫 `#5266AF` 主色，沿用 dsh-Go 原生版的设计语言。

**切页方式**：底部 Tab 调用面板自己的 `<a href="/xxx">`，是 SPA 原生路由——
**不重载、不白屏、不丢终端会话状态**；只有找不到链接时才 `history.pushState` + 兜底整页跳转。
用 `WebBridge.currentRoute()` 低频同步 Tab 高亮，网页内部跳转也能对上。

**网页部分**（`hermes-skin.css` v2）：

- 隐藏桌面侧栏（导航由原生 Tab 接管），内容区占满宽度，单栏卡片流；
- 白卡片 + 18dp 圆角 + 柔和阴影，44dp 触控目标，输入框 ≥16px；
- `/chat` 的 xterm.js 终端收成一张圆角深色代码卡片，不再是一整屏黑终端；
- 只改 CSS，不删 DOM、不覆盖 React 组件、不拦截 fetch。

## 五、为什么功能不会少

工作台始终是 `127.0.0.1:9119` 的完整上游 SPA。这轮所有改动分两类：

1. **补齐 WebView 能力**（文件选择、下载、内容访问）——只加不减；
2. **视觉与导航**（CSS + 调用面板已有链接 + 写面板已有 localStorage 键）——不碰路由、事件、API。

新增的 `hermes-bridge.js` 只挂一个 `window.HermesAndroid` 辅助对象，带 `__v` 版本号幂等去重，
不覆盖任何面板对象。想回到原版视觉，清空 `hermes-skin.css` 即可。

## 还没做的（如实说明）

`/chat` 本质上还是上游内嵌的 TUI 终端，只是被收成卡片。要彻底做成 dsh-Go 那种
气泡式聊天，得改上游前端组件并替换 PTY/WebSocket 交互，那会动到功能代码、风险高。
这版先把「打开、上传、建工作区、像手机 App」四件事做实，真机跑过再决定要不要动前端。
