# 工作台 UI 优化说明

## 为什么 0.1.0 看起来「像 Open Code」

App 是两页结构：**启动页**（原生写的深色金色皮肤，本轮不动）和**工作台**。
工作台是 WebView 全屏承载 Hermes 自带 Web 面板（`http://127.0.0.1:9119/`，
FastAPI + 预构建 SPA，打包在 94 MB rootfs 里）。

上游 `web/src/index.css` 里明确写了：

> JetBrains Mono — bundled for the embedded TUI (/chat tab)

也就是 CHAT 页是 **xterm.js 内嵌终端**，等宽字体 + 深青底（LENS_0 主题
`#041c1c` / `#ffe6cb`）。这就是「巨丑、像 Open Code」的来源，不是 App 壳的锅。

## 本轮做法：只换皮，不砍功能

上游面板是 **token 化样式**（Tailwind v4 + Nous DS），整体视觉由
`--background` / `--midground` / `--theme-*` / `--radius` 等 CSS 变量驱动，
并且自带 `themes/`（`presets.ts` / `skin.ts` / `retint.ts`）主题系统。

所以最稳妥的改法是 **注入一层 CSS 覆盖这些 token**：

- `HermesApp.kt`：Application 生命周期回调里找到 WebView，页面加载完成后触发注入。
  刻意不碰 877 行的 `MainActivity.kt`，零回归风险。
- `ThemeSkin.kt`：只执行 `document.head.appendChild(style)` + 设置 `textContent`。
  **不改 DOM 结构、不拦截请求、不覆盖 JS 对象、不动 localStorage、不动路由**。
- `hermes-skin.css`：换配色（深墨蓝 + 暖白）、中文优先字体栈、加大圆角、
  移动端触控目标 / 滚动条 / 焦点环、给 xterm 终端区加留白与圆角。

**结论：聊天、会话、技能、定时、MCP、配置、KEYS 一个没少**，只是换了层皮。

回滚通道：把 `assets/hermes-skin.css` 清空，`ThemeSkin` 会移除注入的 style，
界面完全回到上游原版。

## 还能继续做的（需要你定风格方向）

1. **深度重皮**：现在只覆盖全局变量与通用元素。要改具体组件（侧栏、消息气泡、
   输入框、工具调用卡片），需要真机截图或对齐上游 `web/` 组件类名再写精确选择器。
2. **直接用上游主题预设**：`themes/presets.ts` 有多套内置主题，若面板支持通过
   localStorage / API 切换，可以做成原生设置里的「主题选择」，换肤更彻底。
3. **原生壳统一**：把启动页金色 `#E8B44A` 也换成同一套墨蓝 + 暖白，内外一致。
4. 若长期维护自定义皮肤，可把注入收敛到 `MainActivity.onPageFinished`（少一个轮询）。

## 签名与仓库卫生（同批改动）

- `build.gradle.kts` 不再写死 `hermes2026`，改为读环境变量或
  `android/keystore.properties`（已被 `.gitignore` 排除）。
- CI 顶层 `env` 从 Secrets 注入 `HERMES_STORE_PASSWORD` / `HERMES_KEY_PASSWORD` /
  `HERMES_KEY_ALIAS`；未配置时回退到现有自签名凭据，**保证构建链不中断**。
- `.gitignore` 从 `/local.properties` 改为 `**/local.properties`，并新增
  `**/keystore.properties`；误提交的 `android/local.properties` 一并删除。

> 如实说明：`keystore/hermes-release.jks` 本身随仓库分发，密码是否明文并不改变
> 安全边界。这次的收益是「凭据不再硬编码在源码、随时可换成 Secret」。
> 若要做正式分发，请把 keystore 移出仓库并更换签名 —— 但那会破坏已有用户的
> 覆盖安装，需要单独规划版本迁移。
