# 3.0：把主屏换成 Today 那种原生 App，不再给网页套壳

## 你反馈的三件事，逐条对应

| 反馈 | 2.0 的实际情况 | 3.0 的做法 |
|---|---|---|
| 「感觉还是一样的」 | 2.0 只是在完整桌面 SPA 外面加了原生顶栏/底栏，**中间那块还是原来的网页**，所以视觉几乎没变 | 主屏整体换成 `TodayHome.kt` 的纯原生 View：全屏蓝紫→白→暖米渐变、圆形悬浮按钮+居中头像、白色聊天气泡流、胶囊输入栏、胶囊底部 5 Tab、卡片式设置页。完整 SPA 退到按需加载的「工作台」层 |
| 「有点卡卡的」 | 三个真实性能源：① `HermesApp` 每 2 秒递归遍历整棵 View 树并往 WebView 打一次 `evaluateJavascript`；② CSS 里几十条 `[class*="..."]` 属性通配选择器 + 通配 `transition`/`box-shadow`，React 每次重渲染都触发全文档样式重算；③ 一启动就把桌面级 SPA 常驻加载 | 删除轮询（改为 `onPageFinished` 一次性注入）；CSS 精简到只覆盖变量与确定选择器；ticker 由 1.2s 降到 2s 且首页状态不执行 JS；**WebView 懒加载**，首屏完全不加载它 |
| 「不好用」 | 首屏是桌面网页，手机上点选、滚动、输入都别扭 | 首屏是原生 View，触控目标 ≥44dp、输入框 ≥16px 不缩放、底部 Tab 单击即切页、右下胶囊一点就发 prompt |

## 二、不是空壳：所有卡片都是真入口

主屏的数据来自本机真实接口，不是写死的假内容：

- `GET /api/status` → 当前模型名；
- `GET /api/sessions?limit=8&order=created` → 最近会话，渲染成气泡卡 / 任务列表；
- 状态变化时只在「刚就绪」那一刻拉一次，不做轮询。

点击行为分两类：

1. **跳面板真实路由**：`/sessions`、`/chat`、`/files`、`/skills`、`/config`、`/models`、`/analytics`、`/mcp`、`/plugins`、`/profiles`、`/env`、`/cron`、`/channels`、`/webhooks`、`/logs`、`/system`（全部从上游 `App.tsx` 里核对过）；
2. **调原生能力**：新建/切换工作区、导入文件、端口与工作区设置、运行日志、导出日志、重启服务、重装运行环境。

输入框不是装饰：回车后把文字立刻回显成右侧气泡，切到 `/chat`，并通过 `WebBridge`-同类脚本把内容注入 xterm 的 `.xterm-helper-textarea`，触发 xterm 的 `input` 采集（`onData → PTY WebSocket`），等于替你敲了一次回车。页面没渲染出终端时会重试最多 12 次；实在拿不到就复制到剪贴板并提示长按粘贴 —— **这条消息永远有办法真的发出去**。

## 三、功能一个没砍

2.0 修好的能力全部保留，且都在工作台层可用：

- `WebChromeClient.onShowFileChooser` + `onActivityResult` 多选 + `allowContentAccess`；
- `DownloadListener` 落盘；
- 原生工作区管理（`Workspaces.kt` + `WebBridge.openWorkspace` 原子写 localStorage）；
- 端口 / 工作目录 / 局域网 / 全自主 / 保持唤醒 / 导出日志 / 重装 / 重启 / 运行日志；
- 工作台层自己的 5 个底部 Tab（SPA 原生路由，不重载、不丢终端会话）。

返回键：在工作台里先回退网页历史，到底后回 Today 首页；在首页才是「再按一次退出」。切回首页只隐藏工作台层、**不销毁 WebView**，终端会话不丢。

桥接层依旧只注入一层 CSS + 一组 `window.HermesAndroid` 辅助函数，不改 DOM、不覆盖 React 组件、不拦截 fetch、不动路由与 API。

## 如实说明边界

`/chat` 本身仍是上游内嵌的 TUI 终端（xterm.js + PTY WebSocket）。3.0 让**主屏**变成 Today 那样的原生气泡流，输入也能真的送进终端，但终端里的回复还是以字符界面呈现，不会变成聊天气泡。要彻底气泡化得替换上游前端组件与 PTY 交互，那会动到功能代码，这版没碰。
